## 3.1 交付物清单（对应原始需求第 4 条）

**【强制】** 每个项目必须交付以下文件，缺一不可：

| 交付物 | 说明 |
|---|---|
| `<项目名>-app.tar` | 离线镜像包，由外部构建机 `docker save` 导出，内网 `docker load` 导入 |
| `docker-compose.yml` | 编排文件，按 §3.3 编写 |
| `init.sh` | 首次部署脚本，契约见 [§5.1](05-脚本行为契约.md) |
| `update.sh` | 版本更新脚本，契约见 [§5.2](05-脚本行为契约.md) |
| `.env.example` | 环境变量模板（**注意拼写为 `example`**，旧文中的 `.env.exsample` 系笔误，已废弃） |
| `deploy/init-db.mariadb.sql`、`deploy/init-db.pgsql.sql` | 建库建用户脚本，供运维按实际数据库执行 |
| `deploy/migrations/` | **版本化数据库迁移**（Alembic 版本目录或 `NNNN_*.sql`）；首次部署与每次升级都必须应用，且必须前后兼容，见 [§5.2](05-脚本行为契约.md) |
| `deploy/gateway-site.conf` | 网关站点配置片段，供运维放入 `conf.d` |
| `frontend/dist/` | 前端构建产物 |
| `Dockerfile` | 镜像构建文件（用于审计与重建；一并交付） |
| `.dockerignore` | 构建上下文裁剪：**必须**排除 `.env*`、`*.tar`、`frontend/node_modules`，否则离线镜像包会被送进构建上下文 |
| `.gitattributes` | 锁定 LF 行尾（`*.sh` / `*.env*` / `*.conf` / `*.sql`），从源头消除 CRLF 问题 |
| `.gitignore` | 版本库排除规则；**必须**含 `.env` 与本地 SQLite 目录 `.local/`（见 [§3.6](03-强制条款.md)、S5） |
| `backend/app/db.py` | **连接串唯一构造点**（模板见 `templates/db.py`）；所有数据库连接必须经它，禁止各自拼串（见 §3.6） |
| `AGENTS.md` | 给 AI 与开发者的**一页红线清单**（vibecoding 场景的第一入口，放交付包根目录） |
| `tools/preflight.sh` | **交付前闸门**脚本（构建机执行；服务器运行不需要，但必须随包交付以便复核） |
| `tools/verify.sh` | **现场验收**脚本（内网服务器执行；读 `.env`，逐项 PASS/FAIL，见 [§6.3](06-交付与验收.md)） |

**【强制】** `docker-compose.yml`、`init.sh`、`update.sh`、`.env.example`、`AGENTS.md`、`tools/`、`deploy/`、`.dockerignore`、`.gitattributes` 全部随交付包提交，不得只给镜像。

**【强制】** 交付前必须在构建机执行 `bash tools/preflight.sh` 并**全部 PASS**，否则禁止交付。

**【强制】** `.sh` 脚本、`.env.example`、`.conf`、`.sql` 必须以 **LF 行尾** 交付（Windows 侧极易变成 CRLF）。自检文件清单是**唯一**的（权威定义见 [§5](05-脚本行为契约.md)）：交付前查 `init.sh update.sh .env.example`，内网生成 `.env` 后追加查 `.env`。交付前自检，期望输出全部为 `0`：

```bash
grep -c $'\r' init.sh update.sh .env.example
```

## 3.2 镜像规范（对应原始需求第 5 条）

**【强制】** 所有环境依赖与业务代码必须全部打进镜像。内网不允许 `pip install`、`npm install`、`apt install`。

**【强制】** 镜像 tag **统一使用 `latest`**（如 `<项目名>-app:latest`），以便 `update.sh` 用固定脚本完成升级——每次交付覆盖同一 tag。

**【强制】** 离线包命名固定为 **`<项目名>-app.tar`**（如 `myapp-app.tar`）。历史版本由 `update.sh` 自动归档到 `backups/` 目录（见 [§5.2](05-脚本行为契约.md)），不在文件名上体现版本。

> **风险提示（已确认接受）**：`latest` 无法从 tag 判断版本，回滚完全依赖 `backups/` 中的归档。因此 **【强制】** `update.sh` 必须执行镜像备份；`update.sh` 还会比对导入前后的镜像 ID，未变化即中止（见 [§5.2](05-脚本行为契约.md)）。

**【强制】** 容器对外**只提供 `0.0.0.0:80` 的服务**。禁止在容器内暴露 8000/8080/3000 等其他业务端口给用户访问；绑定其他端口仅允许用于容器内部通信，且不得写入 `ports:`。

**【强制】** 宿主目录映射**仅限三类**：配置文件、用户上传文件、供用户下载的文件。日志、静态资源、依赖、数据库数据一律不得依赖宿主映射（日志见 §3.5）。

## 3.3 编排规范（对应原始需求第 6 条）

**【强制】** `docker-compose.yml` 必须满足：

| 要求 | 说明 |
|---|---|
| 接入 `gateway-network` | 声明为 `external: true`，不得自行创建 |
| 不定义数据库服务 | 数据库是基础服务，由运维提供；项目**只连接**，`DB_HOST` 取 `mariadb` 或 `pgsql` |
| 不映射宿主端口 | 编排中**不得出现 `ports:`**；对外访问一律经网关 |
| 配置外置 | 所有可变配置放 `.env`，compose 用 `${VAR}` 引用；`.env` 不写死在 compose 里 |
| 日志轮转 | 统一 `json-file` + `max-size: 50m` + `max-file: 3` |
| 服务名 | 容器名固定 `<项目名>-app` |
| 资源限额 | 必须声明 `mem_limit` / `cpus` / `pids_limit`（多项目共用一台服务器，见 §3.5） |
| 不使用 `version:` | Compose v2 已废弃该字段 |

**【强制】** 数据库连接信息**只能**通过 `.env` 注入（`DB_HOST` / `DB_PORT` / `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD`）。禁止硬编码连接串。

**【强制】** `.env` 的值只使用 `[A-Za-z0-9_@%+=:.,-]`，**不得包含 `$`、反引号、引号与空格**。脚本按 shell 语义读取 `.env`，`$` 会被展开成空值，导致口令或连接串**静默**出错——典型现象是"预检全过、部署成功、就是连不上库"。

**【强制】** 应用必须限制数据库连接池（`.env` 的 `DB_POOL_SIZE`，默认 5）。多个项目共用同一个 `mariadb`：**各项目池上限之和必须 ≤ 运维设定的 `max_connections`**，新增项目前须先与运维确认余量。

## 3.4 部署路径与目录（对应原始需求第 7 条）

**【强制】** 项目部署在 **`/home/docker/<项目名>/`**，目录结构固定为：

```
/home/docker/<项目名>/
├── docker-compose.yml        # 编排（根目录）
├── init.sh                   # 首次部署
├── update.sh                 # 版本更新
├── .env                      # 实际配置（chmod 600，不入库、不进镜像）
├── .env.example              # 配置模板
├── <项目名>-app.tar          # 离线镜像包（导入后可删除或归档）
├── conf/                     # 【仅配置】映射为容器 /app/conf:ro
├── uploads/                  # 【用户上传】映射为容器 /data/uploads
├── downloads/                # 【供用户下载】映射为容器 /data/downloads
└── backups/                  # update.sh 自动写入的时间戳快照（.env / docker-compose.yml / 镜像包 / MANIFEST）
```

**【强制】** `<项目名>-app.tar`、`Dockerfile`、`frontend/dist/` 等构建投入物放在交付包中；服务器上运行只需上表所列内容。

**【强制】** `.env` 权限为 `600`，属主为部署用户；`/home/docker/<项目名>/` 属主为部署用户，不得给 `world-writable`。

**【强制】** 宿主 `conf/`、`uploads/`、`downloads/` 的属主必须与**容器运行身份**一致（`.env` 的 `APP_UID:APP_GID`，默认 `1000:1000`）。容器以非 root 运行，属主不一致时容器内无写权限，`uploads/`、`downloads/` 会在现场直接不可写。`init.sh` 会按 `.env` 的 `APP_UID`/`APP_GID` 自动 `chown`；手工部署时必须自行保证。

## 3.5 安全与运行基线

以下条款为评审确认后的强制项，逐条对应可验证手段：

| # | 【强制】条款 | 验证方式 |
|---|---|---|
| S1 | 必须提供 `HEALTHCHECK` 健康检查，且探测路径为 `/api/v1/health` | `docker inspect --format '{{.State.Health.Status}}' <项目名>-app` 返回 `healthy` |
| S2 | 数据库等持久化数据**不得写入容器层**，必须外置（本项目数据在共享数据库，容器内不落库） | 容器 `read_only: true` 可正常启动运行；`docker diff` 无数据目录变更 |
| S3 | 内网离线可用：构建与运行期均不依赖公网 | 前端产物无外链（`bash tools/preflight.sh` 第 7 项）；断网启动成功 |
| S4 | 日志统一输出 stdout/stderr，由 docker 收集；禁止容器内写日志文件 | `docker compose logs` 可看到完整日志；无挂载的日志文件 |
| S5 | 敏感信息一律走 `.env`；禁止硬编码；`.env` 不得提交进包、不得打进镜像 | 镜像内 `grep` 不到口令；`.gitignore` 含 `.env`；`bash tools/preflight.sh` 第 2 项 |
| S6 | 统一 UTF-8 编码与 `Asia/Shanghai` 时区 | 容器内 `date +%z` 返回 `+0800`；数据库为 `utf8mb4`；接口响应体可被 UTF-8 解码且中文不被转义（`ensure_ascii=False`），响应头命中 `Content-Type: application/json` |

**【推荐】**（评审未列为强制，但强烈建议，模板已默认实现）：容器以非 root 用户运行（`user:` 取 `.env` 的 `APP_UID:APP_GID`，默认 uid 1000 + `cap_add: NET_BIND_SERVICE`）、`cap_drop: ALL`、`no-new-privileges: true`、`read_only: true` + `tmpfs`、`init: true`。

**模板已默认实现全部【推荐】项**（见 [§6 交付与验收](06-交付与验收.md) 与 [`templates/`](../templates/README.md)）。资源限额的验收命令见 [§6.3 验收第 13 项](06-交付与验收.md)。如项目因特殊原因需要以 root 运行，可删除 compose 中的 `user:` 与 `cap_add:`，但需在交付说明中写明理由。

## 3.6 数据库引擎开关（本地 SQLite / 内网共享库）

**【强制】** `.env` 必须显式声明 `DB_ENGINE`，取值只能是 `sqlite` / `mariadb` / `pgsql`。**交付包中的默认值是 `mariadb`**，`sqlite` 仅用于本地开发。

| `DB_ENGINE` | 用途 | 连接目标 | 相关键 |
|---|---|---|---|
| `sqlite` | **仅本地开发 / 测试** | 文件库，零依赖 | `DB_SQLITE_PATH`（默认 `.local/dev.db`） |
| `mariadb` | 内网部署 | 运维提供的共享 `mariadb` | `DB_HOST` / `DB_PORT`（3306）/ `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` |
| `pgsql` | 内网部署 | 运维提供的共享 `pgsql` | 同上，`DB_PORT` 为 5432 |

**【强制】** 内网部署**禁止** `DB_ENGINE=sqlite`。原因：容器 `read_only: true` 且未挂持久卷（见 §3.5 S2），sqlite 文件落在容器层里，容器一删数据随之消失——这是**静默的数据丢失**而不是报错，所以必须在动手前拦住。三处闸门：

| 闸门 | 行为 |
|---|---|
| `init.sh` | 预检阶段 `die`（退出码 1），并打印改成 `mariadb` / `pgsql` 的具体做法 |
| `update.sh` | 升级前 `die`（退出码 1）——避免"升级完数据全没了"这类最难排查的故障 |
| `tools/verify.sh` | 验收第 **7b** 项判 `FAIL`（`DB_ENGINE` 缺失或非法同样判失败） |

**【强制】** 连接串必须**只有一个构造点**：`backend/app/db.py`（模板见 [`templates/db.py`](../templates/db.py)）。所有数据库连接（含 ORM、Alembic、迁移脚本）都必须经它取连接串，禁止在业务代码里各自拼接——`grep -rn "DB_HOST" backend/` 应当零命中（`db.py` 自身除外）。该构造点同时保证四件事：

- **口令做 URL 编码**（`quote_plus`）：口令含 `@ : / # ?` 时不会拼出"语法成立、但连到错误主机"的连接串；
- **`mariadb` 显式带 `charset=utf8mb4`**（§3.5 S6），不依赖驱动默认值，避免中文按 latin1 存储而变问号或直接报错；
- **连接池上限取自 `DB_POOL_SIZE`，且 `max_overflow: 0`**：池上限就是硬上限，超出排队而不是继续开连接，以满足 §3.3 的"各项目之和 ≤ `max_connections`"；
- **`pool_pre_ping` + `pool_recycle`**：内网交换机/防火墙会掐掉空闲连接，避免"服务跑了一夜，早上第一个请求必失败"。

**【推荐】** 本地开发切到 sqlite 只需改 `DB_ENGINE` 一行，代码零改动；sqlite 文件默认落在 `.local/`，该目录已在 `.gitignore` 中排除（见 §3.1），不会进版本库、也不会进镜像。
