# 4. 端口、路径与网关接入

> 内网 B/S 架构开发规范 v2.5 · 第 4 章 ｜ [返回总览](../readme.md) ｜ 上一章：[§3 强制条款](03-强制条款.md) ｜ 下一章：[§5 脚本行为契约](05-脚本行为契约.md)

## 4.1 端口分配表

| 位置 | 端口 | 归属 | 是否映射到宿主 |
|---|---|---|---|
| 宿主 | 80 | `nginx-gateway`（运维统一维护） | —（它就是对外入口） |
| 宿主 | 443 | 预留（如需 HTTPS 由运维在网关上启用） | — |
| 容器 `<项目名>-app` | **80** | 本项目应用（FastAPI） | **否** |
| 容器 `mariadb` | 3306 | 共享数据库（运维） | 否 |
| 容器 `pgsql` | 5432 | 共享数据库（运维，待部署） | 否 |

**【强制】** 除网关外，任何项目容器都不得映射宿主端口。多个项目通过**网关的 `server_name` 域名**区分，而非端口。

## 4.2 网关接入流程

1. **开发方**按 [`templates/deploy/gateway-site.conf`](../templates/deploy/gateway-site.conf) 编写 `<项目名>.conf`：
   - 用 `resolver 127.0.0.11 valid=10s ipv6=off;` + 变量指向 `<项目名>-app:80`（**不要用 `upstream` 块**，见下方【强制】）；
   - `server_name` 必须与 `.env` 的 `SITE_DOMAIN` **逐字一致**（域名由运维分配，如 `xz.sjq.sh`，**不得自行编造**），并在**开发启动前**就确认好；
   - `client_max_body_size` 按上传需求设置；`proxy_read_timeout` 按导出/下载耗时设置。
2. **开发方**将 `<项目名>.conf` 随交付包提交（放 `deploy/`）。
3. **运维**将其放入宿主 `/home/docker/nginx/conf.d/`，执行 `nginx -t` 校验后 `nginx -s reload`。
4. 终端访问 `http://<SITE_DOMAIN>/`。

**【强制】** 网关配置文件由开发方提供，运维只负责投放与 reload。开发方不得直接改动宿主的 `conf.d`（该目录为运维职责边界）。

**【强制】** 网关站点配置**必须与控制面一致**：每条 `<项目名>.conf` 都必须对应一个**正在运行**的项目容器。项目下线时必须同步删除该 conf 并 `nginx -s reload`，否则 `nginx -t` / reload 会失败，**所有项目**的入口一起受影响。

**【强制】** 网关站点配置**禁止使用 `upstream` 块**，必须按 [`templates/deploy/gateway-site.conf`](../templates/deploy/gateway-site.conf) 使用 `resolver 127.0.0.11 valid=10s ipv6=off;` + 变量 `proxy_pass http://$app_backend;`。原因：nginx 在解析配置时就固定 `upstream` 主机名，会出现"项目容器未运行时网关起不来（全站挂）"与"容器重建后 IP 变化导致该项目 502"两个问题；用变量形式把解析推迟到请求时，即可把故障范围收敛到单个项目。代价是失去 upstream keepalive 与 `max_fails` 被动健康检查，几十人内网可接受。

## 4.3 域名解析与防串站

**【强制】** 域名解析由运维或终端承担：`<SITE_DOMAIN>` 需在内网 DNS 中存在记录，或在终端 `hosts` 中配置指向虚拟机 IP。开发方交付时必须写明该依赖。

**【强制】** 多人使用的场景应优先由运维在**内网 DNS** 增加 A 记录（或对应的泛解析记录）；`hosts` 只适合 1–2 台机器做验证。

**【推荐】** 单机模拟验证的通行做法：在**目标虚拟机自身**的 `/etc/hosts` 中写入 `<虚拟机 IP>  <SITE_DOMAIN>`，即可在没有内网 DNS 的情况下验证「网关按域名分流」与防串站；验收第 4/5/14 项正是在这种环境下通过 `Host:` 头完成的。**"DNS 已就绪"是上线前置条件**，不是上线后再说的事。

**【强制】** 网关必须存在一个 `default_server` 兜底站点，拒绝未匹配的域名请求。

> **实测发现的风险**：当网关 `conf.d` 中只有一个业务 server 块时，nginx 会把它当作默认站点，于是**任意 `Host` 都能访问到该业务**（实测：不带 `Host` 或 `Host` 为任意值时返回 200）。多项目上线后这一行为会导致**串站**。必须按 [`templates/deploy/gateway-default.conf`](../templates/deploy/gateway-default.conf) 增加兜底 `default_server`（返回 444）。

## 4.5 容器内路径

| 内容 | 容器内路径 | 来源 |
|---|---|---|
| 后端代码 | `/app` | 镜像内 |
| 前端静态产物 | **`/frontend`** | 镜像内（`COPY frontend/dist /frontend`） |
| 配置文件 | `/app/conf`（只读） | 宿主 `conf/` 映射 |
| 用户上传 | `/data/uploads` | 宿主 `uploads/` 映射 |
| 供下载文件 | `/data/downloads` | 宿主 `downloads/` 映射 |

**【强制】** 前端静态资源目录固定为容器内 **`/frontend`**。

**【强制】** 宿主侧 `conf/`、`uploads/`、`downloads/` 的属主必须与**容器运行身份**一致（`.env` 的 `APP_UID:APP_GID`，默认 `1000:1000`，见 [`templates/.env.example`](../templates/.env.example)）。容器以非 root 运行，属主不一致时 `uploads/`、`downloads/` 不可写，上传/下载功能会在现场直接失败；`init.sh` 已按该约定 `chown`。

## 4.6 API 路径规范

**【强制】** 所有接口统一前缀 `/api/v1`，按“`/模块/功能`”组织：

```
/api/v1/<模块>/<功能>            例：POST /api/v1/projects/{id}/archive
/api/v1/<模块>/{id}/<子资源>     例：GET  /api/v1/projects/{id}/events
```

**【强制】** 每个项目必须实现 `GET /api/v1/health`，返回 200 与 JSON 体（供容器健康检查与网关探活使用）。

**【强制】** 除 `GET /api/v1/health` 与**认证入口**外，所有 `/api/v1/**` 接口必须鉴权。认证入口（登录/注册/刷新等，要求先鉴权会构成循环依赖）必须在交付说明中**逐条枚举、禁止通配，通常不超过 3 个**；禁止 `allow_origins=["*"]`（同源 SPA 应直接关闭 CORS）。

## 4.7 静态托管与 SPA 回退（单容器关键实现）

**【强制】** 后端必须以 `/frontend` 为根目录提供 `/` 静态服务，并实现对前端路由的 SPA 回退（任意未命中的前端路径返回 `index.html`）。

**挂载顺序要求**：先注册 `/api/v1` 路由，最后再挂载静态与 SPA 回退；回退逻辑必须显式放行 `/api/` 前缀，避免把接口 404 吞成 `index.html`。

**【强制】** 静态请求必须走统一处理函数，**不得**再 `app.mount("/assets", StaticFiles(...))`——实测 mount 出去的路径会绕开缓存头逻辑，导致构建产物拿不到长缓存头。

可直接复用 [`templates/spa_static.py`](../templates/spa_static.py)，其行为已在真实容器（FastAPI + `/frontend` 挂载）中实测：

| 请求 | 期望结果 | 实测 |
|---|---|---|
| `GET /` | 200 `index.html`，`Cache-Control: no-cache` | ✅ 通过 |
| `GET /assets/<哈希>.js` | 200 真实文件，`Cache-Control: public, max-age=31536000, immutable` | ✅ 通过 |
| `GET /<前端路由>`（如 `/users`） | 200 `index.html`（SPA 回退） | ✅ 通过 |
| `GET /api/v1/<已注册>` | 交给 API 路由 | ✅ 通过 |
| `GET /api/v1/<未注册>` | 404 JSON，**不得**返回 `index.html` | ✅ 通过 |
| `GET /../<越界路径>` | 404（防目录穿越） | ✅ 通过 |
