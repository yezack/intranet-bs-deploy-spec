## 6.1 外部构建机（联网）作业

```bash
# 1) 构建前端产物
cd <项目名>/frontend && npm ci && npm run build      # 产出 dist/

# 2) 构建后端镜像（tag 固定 latest）
cd <项目名> && docker build -t <项目名>-app:latest .

# 3) 导出离线镜像包
docker save <项目名>-app:latest -o <项目名>-app.tar

# 4) 交付前闸门：必须全部 PASS 才允许打包（§3.1 强制）
#    覆盖必需文件、行尾、占位值、编排合规、静态产物外链、镜像架构
bash tools/preflight.sh

# 5) 打包交付（排除 node_modules、.env）
tar czf <项目名>-delivery.tar.gz \
  --exclude='frontend/node_modules' --exclude='.env' \
  docker-compose.yml init.sh update.sh .env.example Dockerfile \
  .dockerignore .gitattributes AGENTS.md tools \
  backend frontend/dist deploy <项目名>-app.tar
```

> **注（构建机架构）**：目标机是 **x86_64**。若构建机为 arm64（Apple Silicon Mac、arm64 云主机），必须在第 2 步的 `docker build` 上自行加 `--platform linux/amd64`——否则内网 `docker load` 会成功，但容器启动报 `exec format error`，现场很难联想到架构问题。`tools/preflight.sh` 第 10 组会检查镜像架构并直接拦下。

## 6.2 内网虚拟机（离线）部署

```bash
# 1) 上传并解包到规范路径
sudo mkdir -p /home/docker/<项目名>
sudo tar xzf <项目名>-delivery.tar.gz -C /home/docker/<项目名>

# 1.5) 校验行尾与可执行位（Windows 传包极易带入 CRLF，或丢失 exec 位导致无法执行）
cd /home/docker/<项目名>
grep -c $'\r' init.sh update.sh .env.example      # 期望全部为 0
sed -i 's/\r$//' init.sh update.sh .env.example   # 若非 0，修正
chmod +x init.sh update.sh                        # Windows 打包通常不带 exec 位

# 2) 生成配置
cd /home/docker/<项目名>
cp .env.example .env && vi .env          # 填强口令；DB_* 由运维提供
chmod 600 .env
grep -c $'\r' .env                       # 期望为 0；变量值带 \r 会导致连不上库等诡异故障
sed -i 's/\r$//' .env                    # 若非 0，修正

# 3) 首次部署
sudo ./init.sh

# 4) 验收
curl -s http://127.0.0.1/api/v1/health -H 'Host: <项目名>.lan'
docker inspect --format '{{.State.Health.Status}}' <项目名>-app
```

## 6.3 验收要点

**推荐直接执行一条命令完成全部检查**（读 `.env`，输出 PASS / WARN / FAIL）：

```bash
cd /home/docker/<项目名> && bash tools/verify.sh
```

逐条对照如下（均为实测可行命令）：

| # | 验收项 | 期望结果 |
|---|---|---|
| 1 | 镜像 tag | `docker images` 中 `<项目名>-app:latest` 存在 |
| 2 | 端口映射 | `docker ps` 中该容器 `PORTS` 列为空（无宿主映射） |
| 3 | 健康状态 | `docker inspect --format '{{.State.Health.Status}}' <项目名>-app` → `healthy` |
| 4 | 网关可达 | `curl -H 'Host: <项目名>.lan' http://127.0.0.1/api/v1/health` → 200 |
| 5 | 前端可达 | `curl -H 'Host: <项目名>.lan' http://127.0.0.1/` → 200 且返回 `index.html` |
| 6 | 网络接入 | 容器接入 `gateway-network` |
| 7 | 配置外置 | 改 `.env` 后 `docker compose up -d --force-recreate` 生效，无需重建镜像 |
| 8 | 敏感信息 | 镜像内搜索不到口令；`.env` 权限 600 |
| 9 | 离线自包含 | 前端产物无外域链接（`bash tools/preflight.sh` 第 7 组）；断网可正常启动 |
| 10 | 日志 | `docker compose logs` 有输出；容器内无日志文件 |
| 11 | 时区/编码 | `docker exec <项目名>-app date +%z` → `+0800`；库为 `utf8mb4`（`SHOW CREATE DATABASE`）；接口响应可 UTF-8 解码且中文不被转义 |
| 12 | 脚本契约 | `init.sh` 可重复执行；`update.sh` 能备份、能回滚 |
| 13 | 资源限额 | `docker inspect --format '{{.HostConfig.Memory}}' <项目名>-app` → `536870912`；`{{.HostConfig.PidsLimit}}` → `256` |
| 14 | **防串站** | `curl -s -o /dev/null -w '%{http_code}' -H 'Host: <项目名>-nope.lan' http://127.0.0.1/` → **非 200**（缺 `default_server` 时任意 `Host` 都会命中业务，见 [§4.3](04-端口路径与网关接入.md)） |
| 15 | 域名解析 | `getent hosts <项目名>.lan` 有输出；仅用 `hosts` 的 1–2 台机器场景可跳过（见 [§4.3](04-端口路径与网关接入.md)） |

## 6.4 常用运维命令

```bash
cd /home/docker/<项目名>
sudo docker compose ps                  # 状态
sudo docker compose logs -f --tail=200  # 日志
sudo docker compose restart             # 重启
sudo docker compose down                # 停止（数据在共享库，不受影响）
sudo ./update.sh                        # 升级（自动备份 + 失败回滚）
sudo docker compose up -d --force-recreate   # 改 .env 后重新应用
```

## 6.5 项目下线（共享服务器必须执行的收尾）

**【强制】** 项目停止使用时必须按序完成以下收尾；缺步会在共享服务器上留下隐患。

```bash
# 1) 停容器（不动共享数据库）
cd /home/docker/<项目名> && sudo docker compose down --remove-orphans

# 2) 清理历史项目内网（当前模板只接 gateway-network；v2.1 之前的项目可能残留 <项目名>-net）
sudo docker network rm <项目名>-net 2>/dev/null || true

# 3) 通知运维删除网关站点配置并 reload —— 这一步不能省
#    sudo rm /home/docker/nginx/conf.d/<项目名>.conf
#    sudo docker exec nginx-gateway nginx -t && sudo docker exec nginx-gateway nginx -s reload

# 4) 通知运维删除内网 DNS 中 <项目名>.lan 的记录（使用泛解析的可跳过）

# 5) 数据库：先备份为 SQL 文件存档，再由运维决定保留或删除库与账号
#    docker exec mariadb mysqldump -u<user> -p'<口令>' <库名> > <项目名>-final.sql

# 6) 归档后删除部署目录（含 backups/ 与历史镜像包），释放磁盘
#    sudo mkdir -p /home/docker/archive
#    sudo tar czf /home/docker/archive/<项目名>-$(date +%F).tar.gz -C /home/docker <项目名>
#    sudo rm -rf /home/docker/<项目名>
```

**第 3 步与第 6 步不得省略**：残留的 `<项目名>.conf` 会让 `nginx -t` / reload 失败，从而影响**所有项目**的入口（见 [§4.2](04-端口路径与网关接入.md)）；不释放磁盘则是共享服务器磁盘耗尽的常见来源。
