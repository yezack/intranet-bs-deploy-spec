## 2.1 部署拓扑

```
                        ┌──────────────────────────────────────────┐
   内网终端             │            内网 Linux 虚拟机              │
  （浏览器）            │                                          │
      │                 │   ┌────────────────────────────────┐     │
      │  http://         │   │  nginx-gateway（运维统一维护）  │     │
      │  <项目名>.lan    │   │  nginx:1.27-alpine             │     │
      └─────────────────┼──▶│  0.0.0.0:80  ← 唯一对外端口      │     │
                        │   │  挂载 /home/docker/nginx/conf.d │     │
                        │   └───────────────┬────────────────┘     │
                        │                   │ proxy_pass            │
                        │                   ▼                       │
                        │   ┌────────────────────────────────┐     │
                        │   │  <项目名>-app（本项目，唯一容器）│     │
                        │   │  FastAPI 监听 0.0.0.0:80        │     │
                        │   │  静态：/frontend  SPA           │     │
                        │   │  接口：/api/v1/**               │     │
                        │   │  无宿主端口映射                 │     │
                        │   └───────────────┬────────────────┘     │
                        │                   │ gateway-network       │
                        │                   ▼                       │
                        │   ┌────────────────────────────────┐     │
                        │   │  mariadb:10.11 / pgsql（运维）  │     │
                        │   │  仅内网 3306/5432，无端口映射   │     │
                        │   └────────────────────────────────┘     │
                        └──────────────────────────────────────────┘
```

**关键设计**：本项目**只有一个容器**。FastAPI 自身监听 80 端口，同时提供前端静态资源与 API——即原始需求第 3 条“后端应将 `/` 路径静态解析至 `/frontend` 文件夹”的字面落地（原文见[附录](07-附录.md)）。

**【强制】** 项目内**不再设置 nginx 容器**。静态资源由后端进程托管，反向代理与 TLS 由运维的统一网关负责。

## 2.2 基准环境（实测值）

以下为 2026-09-29 在基础环境中实测确认的基准值，规范中的具体数值均以此为准：

| 项 | 实测值 | 说明 |
|---|---|---|
| 操作系统 | Linux（x86_64） | 实测环境 |
| Docker | 28.5.2 | 服务 `docker` active |
| Docker Compose | v2.35.1 | **不再写 `version:` 字段** |
| 统一网关 | 容器 `nginx-gateway`，`nginx:1.27-alpine`（1.27.5） | 独占宿主 `0.0.0.0:80`，由 `docker-proxy` 持有 |
| 网关配置目录 | 宿主 `/home/docker/nginx/conf.d/` → 容器 `/etc/nginx/conf.d` | 运维维护 |
| 共享数据库 | 容器 `mariadb`，`mariadb:10.11` | 仅内网 3306，无宿主端口映射 |
| 网关网络 | `gateway-network`，bridge，`172.18.0.0/16` | 已存在，项目以 `external: true` 接入 |
| 工程根目录 | `/home/docker/`（root:root 0755） | 项目落在 `/home/docker/<项目名>/` |
| 部署用户 | 普通用户（非 root），**不在 `docker` 组** | 执行 docker 命令需 `sudo` |
| 宿主 80 端口 | 仅 `docker-proxy` 监听 | 宿主机自带的 nginx/mariadb 服务必须停用，避免抢占 80 / 3306 |

**【强制】** 若目标虚拟机的实测值与上表不一致（尤其是 Docker/Compose 版本、网络网段、数据库容器名），必须先与运维确认后再部署，不得沿用旧假设。
